[`CLDK`](https://github.com/codellm-devkit/python-sdk) is a Python SDK on [PyPI](https://pypi.org/project/cldk/). You can install it with any Python package manager.

## Installation

Use [pip](https://pypi.org/project/pip/), [poetry](https://python-poetry.org/), or [uv](https://docs.astral.sh/uv/):

<Tabs>
  <TabItem label="pip">
    ```bash
    pip install cldk
    ```
  </TabItem>
  <TabItem label="poetry">
    ```shell
    poetry add cldk
    ```
  </TabItem>
  <TabItem label="uv">
    ```shell
    uv add cldk
    ```
  </TabItem>
</Tabs>

<Aside type="note" title="CLDK 2.0 is a release candidate">
Dataflow levels, `taint()`, and the other 2.0 methods are not in the stable release. `pip install cldk` gives you 1.5.0. To get the pre-release, run `pip install --pre cldk`. In 2.0, the Java backend is an optional extra. For Java analysis, run `pip install --pre "cldk[java]"` instead. See [Dataflow graphs](/guides/dataflow/).
</Aside>

## Language-specific dependencies

CLDK analyzes several languages. Each language needs its own dependencies:

<Tabs>
  <TabItem label="Python Analysis">
    The CLDK Python SDK and Python analysis both need Python 3.11 or later. [pyenv](https://github.com/pyenv/pyenv) installs and manages several Python versions on one machine.
  </TabItem>
  <TabItem label="Java Analysis">
    For Java analysis, CLDK uses a companion backend, [`codeanalyzer-java`](/backends/codeanalyzer-java/). In CLDK 2.0, install it as an extra: `pip install --pre "cldk[java]"`. The backend carries its own JVM. To build the target project with Maven, you need the Java Development Kit (JDK), version 11 or later.

    [SDKMAN](https://sdkman.io/) installs and manages JDK versions.

    - Install SDKMAN with this command:

      ```bash
      curl -s "https://get.sdkman.io" | bash
      ```

    - Open a new terminal, or load the SDKMAN scripts:

      ```bash
      source "$HOME/.sdkman/bin/sdkman-init.sh"
      ```

    Next, install Java 11 or later with SDKMAN:

    - List the available Java versions:

      ```bash
      sdk list java | grep sem
      ```

      The output looks like this:
      ```bash
      Semeru      |     | 21.0.5       | sem     |            | 21.0.5-sem
                  |     | 17.0.13      | sem     |            | 17.0.13-sem
                  |     | 11.0.25      | sem     |            | 11.0.25-sem
                  |     | 8.0.432      | sem     |            | 8.0.432-sem
      ```

    - Install Java 11 or later. This example uses `11.0.25-sem`:

      ```bash
      sdk install java 11.0.25-sem
      ```

    - Set Java 11 as the current (or default) Java version:

      ```bash
      sdk use java 11.0.25-sem
      # If want to default to java 11 for all sessions, use the following command instead:
      # sdk default java 11.0.25-sem
      ```

    - Make sure that the installation works:

      ```bash
      java -version
      ```

      The command shows the installed Java version.

      ```bash
      openjdk 11.0.25 2024-10-15
      IBM Semeru Runtime Open Edition 11.0.25.0 (build 11.0.25+9)
      Eclipse OpenJ9 VM 11.0.25.0 (build openj9-0.48.0, JRE 11 Linux amd64-64-Bit Compressed References 20241107_1233 (JIT enabled, AOT enabled)
      OpenJ9   - 1d5831436e
      OMR      - d10a4d553
      JCL      - edded3f65c based on jdk-11.0.25+9)
      ```

    Finally, for call graphs and deeper levels, the Java backend builds your project automatically with Maven or Gradle. For a Maven project, install Maven with SDKMAN:

    - Install Maven:

      ```bash
      sdk install maven
      ```

    - The `mvn` command must be on your `PATH`. If it is not, add this line to your `~/.zshrc`, `~/.bashrc`, or `~/.bash_profile` file:

      ```bash
      export PATH="$HOME/.sdkman/candidates/maven/current/bin:$PATH"
      ```
      Then load the file again:

      ```bash
      source ~/.zshrc # or ~/.bashrc or ~/.bash_profile
      ```

    - Make sure that the installation works:

      ```bash
      mvn -version
      ```
      The command shows the installed Maven version.
  </TabItem>
  <TabItem label="TypeScript Analysis">
    For TypeScript and JavaScript analysis, CLDK uses a companion backend, [`codeanalyzer-ts`](/backends/codeanalyzer-ts/). The prebuilt binary itself needs no Bun or Node. To install the dependencies of your project, the backend needs `npm`, which ships with Node. The `cldk` package installs `codeanalyzer-typescript` at the version that CLDK pins, so the SDK needs no separate install. The package adds a `cants` command to your `PATH`. To install only the command, use PyPI or Homebrew.

    Install it from PyPI:

    ```bash
    pip install codeanalyzer-typescript
    ```

    Or with Homebrew:

    ```bash
    brew install codellm-devkit/homebrew-tap/codeanalyzer-typescript
    ```

    Make sure that the installation works:

    ```bash
    cants --help
    ```

    The package is named `codeanalyzer-typescript`, but the command is **`cants`**. To resolve library call targets, the backend needs the dependencies of the project. If `npm` is on your `PATH`, the backend creates `node_modules` for you. To skip this step, use `--no-build`. For the full list of CLI options, see the [codeanalyzer-ts backend reference](/backends/codeanalyzer-ts/).
  </TabItem>
  <TabItem label="IaC Analysis">
    For infrastructure-as-code analysis, the companion backend is [`codeanalyzer-iac`](/backends/codeanalyzer-iac/). Its command is `caniac`. It ships as a prebuilt binary and needs no Helm CLI.

    Install it from PyPI:

    ```bash
    pip install codeanalyzer-iac
    ```

    Or with Homebrew:

    ```bash
    brew install codellm-devkit/tap/codeanalyzer-iac
    ```

    Make sure that the installation works:

    ```bash
    caniac --help
    ```

    There is no `CLDK.iac(...)` factory yet. Run `caniac` as a command, or read the Neo4j graph that it writes. For the analysis levels and output modes, see the [codeanalyzer-iac backend reference](/backends/codeanalyzer-iac/).
  </TabItem>
  <TabItem label="Rust Installation">
    CLDK does not analyze Rust yet. You need a Rust toolchain only to contribute Rust code, for example the [Rust frontend](/contributing/rust-frontend/). Use rustup to install Rust and manage toolchains. rustup keeps Rust versions separate, and you can change between them.

    - **Install rustup.**
    Run this command in your terminal:
    ```shell
    curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
    ```
    Then follow the instructions on screen.

    - **Configure your environment.**
    Add this line to your shell init script:
    ```shell
    source $HOME/.cargo/env
    ```

    - **Make sure that the installation works.**
    Show the version:
    ```shell
    rustc --version
    ```
    The output looks like this. The version number can be different:
    ```shell
    rustc 1.70.0 (90c541806 2023-05-31)
    ```
  </TabItem>
</Tabs>

## Additional development tools

If you build Python from source, for example with pyenv, some operating systems need additional development tools:

<Tabs>
  <TabItem label="macOS">
    - Install the Xcode Command Line Tools:

      ```shell
      xcode-select --install
      ```

    - Some builds also need these Homebrew packages:

      ```shell
      brew install openssl readline sqlite3 xz zlib tcl-tk libffi
      ```
  </TabItem>
  <TabItem label="Ubuntu/Debian">
    - Install the build tools:

      ```shell
      sudo apt-get install build-essential python3-dev libssl-dev zlib1g-dev \
      libbz2-dev libreadline-dev libsqlite3-dev curl git \
      libncursesw5-dev xz-utils tk-dev libxml2-dev libxmlsec1-dev libffi-dev liblzma-dev
      ```
  </TabItem>
  <TabItem label="Red Hat (Fedora/CentOS/RHEL)">
    - Install the build tools:

      ```shell
      sudo dnf group install c-development development-tools gcc make \
      patch zlib-devel bzip2 bzip2-devel readline-devel sqlite sqlite-devel\
      openssl-devel tk-devel libffi-devel xz-devel
      ```
  </TabItem>
</Tabs>
