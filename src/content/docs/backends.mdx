**Standalone language backends** parse the source, resolve the symbols, and build the call graph. There is one backend for each language, and one more for infrastructure-as-code. Together they are the `codeanalyzer-*` tools. Each backend writes typed JSON. The SDK reads that JSON and builds models that you can query.

```mermaid
flowchart LR
    SDK["CLDK Python SDK<br/>(analysis API)"] -->|invokes| CAJ["codeanalyzer-java<br/>(JVM · WALA)"]
    SDK -->|invokes| CAP["codeanalyzer-python<br/>(Jedi · defuse linker)"]
    SDK -->|invokes| CAT["codeanalyzer-ts<br/>(TS compiler)"]
    CAJ -->|canonical JSON| SDK
    CAP -->|canonical JSON| SDK
    CAT -->|canonical JSON| SDK
```

This split lets one `analysis` API cover many languages. The SDK does not parse code itself. It runs the correct backend. Then it maps the backend JSON onto typed models (`JApplication`, `PyModule`, and others).

A new backend that writes the canonical JSON makes its language available to the SDK. The SDK then needs only the Python bindings for that language. See [Add a language backend](/contributing/add-language-backend/).

<Aside type="note" title="The SDK manages the backends">
The SDK runs each backend for you. <Badge text="2.0" variant="caution" /> The Java backend is the optional extra `cldk[java]`. Its wheel carries the JAR and a bundled JVM, and the SDK runs `java -jar` on that JVM. Analysis level 2 and above also need a JDK 11 or later on `JAVA_HOME`. In CLDK 1.5.0, the SDK downloads a Temurin JDK on first use instead.

The `codeanalyzer-python` and `codeanalyzer-typescript` packages are dependencies of `cldk`. The SDK imports the Python backend in-process, and the backend creates a virtualenv for the dependencies of the analyzed project. You do not download a JAR, and you do not set `analysis_backend_path`.

These pages document the backend layer for readers who want to understand it or add to it.
</Aside>

This is the **backend** layer. For the SDKs that consume it, see the [SDKs overview](/reference/sdks/).

## Backends

The `codeanalyzer-*` tools parse a language. Then they write the canonical symbol-table and call-graph schema that every frontend reads.

| Language | Backend | Maturity |
| --- | --- | --- |
| **Java** | [codeanalyzer-java](/backends/codeanalyzer-java/) | <Badge text="Mature" variant="success" /> |
| **Python** | [codeanalyzer-python](/backends/codeanalyzer-python/) | <Badge text="Mature" variant="success" /> |
| **TypeScript** | [codeanalyzer-ts](/backends/codeanalyzer-ts/) | <Badge text="Mature" variant="success" /> |
| **JavaScript** | via [codeanalyzer-ts](/backends/codeanalyzer-ts/) | <Badge text="Medium" variant="tip" /> |
| **IaC (Helm)** | [codeanalyzer-iac](/backends/codeanalyzer-iac/) | <Badge text="Beta" variant="caution" /> |
