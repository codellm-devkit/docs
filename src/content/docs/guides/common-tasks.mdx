This page is a task index. Each section states a question about a codebase. It then shows the CLDK call and the shape of the result. The call comes first, and the output follows as a trailing comment. Java examples use [Apache Commons CLI](https://commons.apache.org/proper/commons-cli/) (`project_path="commons-cli"`). Python examples use a generic `my_pkg`.

<Aside type="tip" title="Build once, query many times">
One `analysis` object serves many queries. The default analysis level is `symbol_table`. Any query that touches the call graph (callers, callees) needs `analysis_level=AnalysisLevel.call_graph`. See [Concepts](/guides/concepts/) for what each level populates.
</Aside>

## List all methods in a class

List every method declared on a class.

<Tabs syncKey="lang">
  <TabItem label="Python">
    ```python
    from cldk import CLDK

    analysis = CLDK.python(project_path="my_pkg")

    pyclass = analysis.get_classes()["my_pkg.options.Options"]
    for method in pyclass.methods.values():
        print(method.signature)
    # add_option(self, option)
    # get_option(self, name)
    # has_option(self, name)
    # ...
    ```
  </TabItem>
  <TabItem label="Java">
    ```python
    from cldk import CLDK

    analysis = CLDK.java(project_path="commons-cli")

    klass = "org.apache.commons.cli.Options"
    methods = analysis.get_methods()[klass]
    for signature in methods:
        print(signature)
    # Parameter types in each signature are fully qualified:
    # addOption(org.apache.commons.cli.Option)
    # addOption(java.lang.String, boolean, java.lang.String)
    # getOption(java.lang.String)
    # hasOption(java.lang.String)
    # ...
    ```
  </TabItem>
</Tabs>

## Get the source body of a method

Get the exact source of one method by its qualified class name and signature. You do not read files or track line ranges.

<Tabs syncKey="lang">
  <TabItem label="Python">
    ```python
    method = analysis.get_method(
        "my_pkg.options.Options",
        "add_option",
    )
    print(method.code)
    # def add_option(self, option):
    #     self._options[option.name] = option
    #     return self
    ```
  </TabItem>
  <TabItem label="Java">
    ```python
    method = analysis.get_method(
        "org.apache.commons.cli.Options",
        "addOption(org.apache.commons.cli.Option)",
    )
    print(method.code)
    # public Options addOption(Option opt) {
    #     String key = opt.getKey();
    #     ...
    #     return this;
    # }
    ```
  </TabItem>
</Tabs>

<Aside type="note">
If the method is not found, `get_method(...)` returns `None`. Test with `if method:` before you read `.code`. The returned object is a `JCallable` (Java) or a `PyCallable` (Python).
</Aside>

## Build a call graph

The call graph is a `networkx.DiGraph`. Its edges point from **caller** to **callee**. The callers and callees queries both use it, so they need the `call_graph` analysis level.

<Tabs syncKey="lang">
  <TabItem label="Python">
    ```python
    from cldk import CLDK
    from cldk.analysis import AnalysisLevel

    analysis = CLDK.python(
        project_path="my_pkg",
        analysis_level=AnalysisLevel.call_graph,  # required for call edges
    )

    cg = analysis.get_call_graph()
    print(cg.number_of_nodes(), "methods,", cg.number_of_edges(), "edges")
    # 87 methods, 113 edges
    ```
  </TabItem>
  <TabItem label="Java">
    ```python
    from cldk import CLDK
    from cldk.analysis import AnalysisLevel

    analysis = CLDK.java(
        project_path="commons-cli",
        analysis_level=AnalysisLevel.call_graph,  # required for call edges
    )

    cg = analysis.get_call_graph()
    print(cg.number_of_nodes(), "methods,", cg.number_of_edges(), "edges")
    # 421 methods, 638 edges
    ```
  </TabItem>
</Tabs>

## Find who calls a method

Impact analysis. `get_callers` returns the set of methods that call the target.

<Tabs syncKey="lang">
  <TabItem label="Python">
    ```python
    callers = analysis.get_callers(
        "my_pkg.options.Options",
        "add_option",
    )
    print(list(callers))
    # ['my_pkg.cli.build_options', 'my_pkg.options.Options.add_required', ...]
    ```
  </TabItem>
  <TabItem label="Java">
    ```python
    callers = analysis.get_callers(
        "org.apache.commons.cli.Options",
        "addOption(org.apache.commons.cli.Option)",
    )
    print(list(callers))
    # ['org.apache.commons.cli.Options.addOption(java.lang.String, boolean, java.lang.String)',
    #  'org.apache.commons.cli.DefaultParser.handleOption(...)', ...]
    ```
  </TabItem>
</Tabs>

<Aside type="tip" title="Inspect the shape once">
`get_callers` and `get_callees` return dictionaries. The exact keys depend on your CLDK and backend version. The first time you use them, print one result with `print(callers)`, or with `json.dumps(callers, default=str, indent=2)`. Then index the fields that your version returns.
</Aside>

## Find what a method calls

The dependency view. `get_callees` is the inverse of `get_callers`. It returns the methods that the target calls.

<Tabs syncKey="lang">
  <TabItem label="Python">
    ```python
    callees = analysis.get_callees(
        "my_pkg.parser.DefaultParser",
        "parse",
    )
    print(list(callees))
    # ['my_pkg.options.Options.get_option', 'my_pkg.cli.CommandLine.add_option', ...]
    ```
  </TabItem>
  <TabItem label="Java">
    ```python
    callees = analysis.get_callees(
        "org.apache.commons.cli.DefaultParser",
        "parse(org.apache.commons.cli.Options, java.lang.String[])",
    )
    print(list(callees))
    # ['org.apache.commons.cli.Options.getOption(java.lang.String)',
    #  'org.apache.commons.cli.CommandLine.addOption(org.apache.commons.cli.Option)', ...]
    ```
  </TabItem>
</Tabs>

## Map the class hierarchy

In Java, walk class relationships with `get_sub_classes`, `get_extended_classes`, and `get_implemented_interfaces`.

<Tabs syncKey="lang">
  <TabItem label="Python">
    ```python
    # Python analysis does not expose get_class_hierarchy / get_sub_classes.
    # Recover base classes from the model: each PyClass records its bases.
    pyclass = analysis.get_classes()["my_pkg.parser.DefaultParser"]
    print(pyclass.base_classes)
    # ['my_pkg.parser.Parser']
    ```
  </TabItem>
  <TabItem label="Java">
    ```python
    parser = "org.apache.commons.cli.Parser"
    print(analysis.get_sub_classes(parser))
    # {'org.apache.commons.cli.BasicParser', 'org.apache.commons.cli.GnuParser', ...}

    print(analysis.get_implemented_interfaces("org.apache.commons.cli.DefaultParser"))
    # {'org.apache.commons.cli.CommandLineParser'}
    ```
  </TabItem>
</Tabs>

<Aside type="note">
Class-relationship helpers (`get_sub_classes`, `get_extended_classes`, `get_implemented_interfaces`) are part of the **Java** API. For Python, read the base classes from the `PyClass` model instead, as shown above.
</Aside>

## Find data-access / CRUD operations

Find where the code reads or writes persistent data. This helps with security triage and data-flow analysis. It is a **Java-only** feature.

<Tabs syncKey="lang">
  <TabItem label="Python">
    ```python
    # Not available. CRUD-operation extraction (get_all_crud_operations)
    # is part of the Java analysis API only.
    ```
  </TabItem>
  <TabItem label="Java">
    ```python
    crud = analysis.get_all_crud_operations()
    for entry in crud:
        print(entry)
    # JCRUDOperation(operation_type='READ',  ...)
    # JCRUDOperation(operation_type='CREATE', ...)
    # ...
    ```
  </TabItem>
</Tabs>
