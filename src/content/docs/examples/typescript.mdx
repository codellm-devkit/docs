import { Aside, Badge, LinkCard, CardGrid } from "@astrojs/starlight/components";

These examples run against [Zod](https://github.com/colinhacks/zod), a TypeScript schema declaration library, and its published package `zod/packages/zod`. Each example calls one method of the CLDK Python SDK. The outputs come from cldk 2.0.0 (codeanalyzer-typescript 1.6.0) on Zod 4.6.7.

A section with the <Badge text="2.0" variant="caution" /> badge uses a method that is new in CLDK 2.0. If you have CLDK 1.x, upgrade with `pip install -U cldk`. If you analyzed Zod with CLDK 1.x, the cache from that run makes `CLDK.typescript` raise a `ValidationError` for `TSAnalysis`. To fix it, delete `zod/packages/zod/.codeanalyzer`. You can also pass `eager=True` to `CLDK.typescript` once.

<Aside type="note" title="Project-based analysis">
TypeScript analysis is project-based. `project_path` must point at a project directory. There is no single-file mode. The backend also analyzes `.js`, `.jsx`, `.mjs`, and `.cjs` files in that directory.
</Aside>

## Set up the analysis

Clone Zod 4.6.7 first.

```bash
git clone --depth 1 --branch v4.6.7 https://github.com/colinhacks/zod.git
```

Then point CLDK at the published package. Run Python from the directory that contains `zod`.

```python
from cldk import CLDK
from cldk.analysis import AnalysisLevel

analysis = CLDK.typescript(
    project_path="zod/packages/zod",
    analysis_level=AnalysisLevel.call_graph,
)
```

The other code blocks on this page continue this block. The `zod/packages/zod` directory holds both the v3 and the v4 source trees. A signature under one of those trees carries a `src/v3` or a `src/v4` prefix. The default analysis level builds the symbol table only. The `call_graph` level adds the caller and callee edges.

The backend reuses a cached `analysis.json` at any level. If an earlier run wrote that cache at the symbol-table level, pass `eager=True` once.

```python
analysis = CLDK.typescript(
    project_path="zod/packages/zod",
    analysis_level=AnalysisLevel.call_graph,
    eager=True,
)
```

## Symbol table: modules, classes, and methods

### List all modules

The symbol table holds one `TSModule` per source file. Each key is the package-relative file path with its extension.

```python
modules = analysis.get_modules()
print(len(modules), "modules")
# 135 modules

symbol_table = analysis.get_symbol_table()
for file_path in sorted(symbol_table)[:5]:
    print(file_path)
# src/compile.ts
# src/index.ts
# src/locales/index.ts
# src/mini/index.ts
# src/v3/ZodError.ts
```

### List all classes

A class signature is the file path without its extension, then the dotted member path.

```python
classes = analysis.get_classes()
print(len(classes), "classes")
# 53 classes

for signature in sorted(classes)[:6]:
    print(signature)
# src/v3/ZodError.ZodError
# src/v3/helpers/parseUtil.ParseStatus
# src/v3/types.Class
# src/v3/types.ParseInputLazyPath
# src/v3/types.ZodAny
# src/v3/types.ZodArray
```

### Get one class

Get one class by its signature. Read `methods` from the `TSClass` that comes back. The key of a getter ends in `#get`. The key of an arrow function in a class property is its position: `<anon@298:14>` is line 298, column 14.

```python frame="none"
tsclass = analysis.get_class("src/v3/ZodError.ZodError")
print(tsclass.signature)
# src/v3/ZodError.ZodError

print(sorted(tsclass.methods))
# ['<anon@298:14>', '<anon@302:15>', 'assert', 'constructor', 'errors#get', 'flatten', 'formErrors#get', 'format', 'isEmpty#get', 'message#get', 'toString']
```

### List the fields of a class

Get every field of one class. Each field is a `TSField` with a `name` and a `type`. `ZodArray` has one field, the static `create` function.

```python
fields = analysis.get_fields("src/v3/types.ZodArray")
for field in fields:
    print(field.name, field.type)
# create <El extends ZodTypeAny>(schema: El, params?: RawCreateParams) => ZodArray<El>
```

### Get one method

Get one method by the class signature and the method name. Read its source from `code`.

```python frame="none"
method = analysis.get_method("src/v3/ZodError.ZodError", "toString")
print(method.signature)
# src/v3/ZodError.ZodError.toString

print(method.return_type)
# string

print(method.code)
# override toString() {
#     return this.message;
#   }
```

### Filter classes by name

`get_classes_by_criteria` keeps each class whose signature contains an inclusion string and no exclusion string.

```python
matches = analysis.get_classes_by_criteria(
    inclusions=["ZodError"],
    exclusions=["v4"],
)
for signature in sorted(matches):
    print(signature)
# src/v3/ZodError.ZodError
```

### List imports

Get the imports of every module, keyed by file path. Each entry is a `TSImport` with the imported name, the module specifier, and the resolved module key. Zod imports `.js` paths, and the backend resolves them to the `.ts` files.

```python
imports = analysis.get_imports()
for imp in imports["src/v3/ZodError.ts"]:
    print(imp.name, "from", imp.module, "->", imp.resolved_module)
# Primitive from ./helpers/typeAliases.js -> src/v3/helpers/typeAliases.ts
# util from ./helpers/util.js -> src/v3/helpers/util.ts
# ZodParsedType from ./helpers/util.js -> src/v3/helpers/util.ts
# TypeOf from ./index.js -> src/v3/index.ts
# ZodType from ./index.js -> src/v3/index.ts
```

## Type declarations: interfaces, enums, and type aliases

The TypeScript analysis has methods for interfaces, enums, and type aliases. The Python analysis does not have these methods. Zod declares its error types in `src/v3/ZodError.ts`.

### List interfaces

Zod declares an interface for each kind of validation issue.

```python frame="none"
interfaces = analysis.get_interfaces()
for signature in sorted(interfaces)[:4]:
    print(signature)
# src/v3/ZodError.ZodCustomIssue
# src/v3/ZodError.ZodInvalidArgumentsIssue
# src/v3/ZodError.ZodInvalidDateIssue
# src/v3/ZodError.ZodInvalidEnumValueIssue
```

### List enums

Zod declares two enums, one in each source tree.

```python frame="none"
for signature in sorted(analysis.get_enums()):
    print(signature)
# src/v3/types.ZodFirstPartyTypeKind
# src/v4/classic/compat.ZodFirstPartyTypeKind
```

To read the members of one enum, call `get_enum_members` with the enum signature. Each member holds a `name` and a `value`.

```python
for member in analysis.get_enum_members("src/v3/types.ZodFirstPartyTypeKind")[:4]:
    print(member.name, "=", member.value)
# ZodString = ZodString
# ZodNumber = ZodNumber
# ZodNaN = ZodNaN
# ZodBigInt = ZodBigInt
```

### List type aliases

A type alias keeps the same signature shape as a class or an interface.

```python frame="none"
type_aliases = analysis.get_type_aliases()
for signature in sorted(type_aliases)[:6]:
    print(signature)
# src/v3/ZodError.DenormalizedError
# src/v3/ZodError.ErrorMapCtx
# src/v3/ZodError.IssueData
# src/v3/ZodError.StringValidation
# src/v3/ZodError.ZodErrorMap
# src/v3/ZodError.ZodFormattedError
```

## Decorators

### Read the decorators

The backend captures each decorator with its arguments. Pass a class signature to `get_class_decorators`. Pass a list of decorator names to `get_methods_with_decorators`. Zod uses no decorators, so both calls return empty results.

```python
print(analysis.get_class_decorators("src/v3/types.ZodArray"))
# []

print(analysis.get_methods_with_decorators(["Get"]))
# {'Get': []}
```

## Call graph: callers, callees, and reachability

Every call-graph query needs `analysis_level=AnalysisLevel.call_graph`. The default level builds the symbol table only, and it resolves no call targets.

### Build the call graph

The call graph is a `networkx.DiGraph`, and its edges point from the caller to the callee.

```python
cg = analysis.get_call_graph()
print(cg.number_of_nodes(), "nodes,", cg.number_of_edges(), "edges")
# 2261 nodes, 4629 edges
```

### List the external targets

An external symbol is a call target that the backend never analyzed. Its key is the module name and the symbol name. A runtime built-in has the module name `(builtin)`.

```python
externals = sorted(analysis.get_external_symbols())
print(externals[:4])
# ['(builtin).abs', '(builtin).add', '(builtin).all', '(builtin).apply']
```

### Find the callers of a method

The result holds `target_method` and a list of `caller_details`. Each entry in `caller_details` holds a `caller_signature` and an `edge` with `type`, `weight`, and `provenance`. The `provenance` tuple names the resolver that found the edge. The name `<anon@2305:14>` is an anonymous function at line 2305, column 14.

```python
callers = analysis.get_callers(
    target_class_name="src/v3/helpers/parseUtil.ParseStatus",
    target_method_declaration="mergeArray",
)
print(callers["target_method"])
# src/v3/helpers/parseUtil.ParseStatus.mergeArray

for detail in callers["caller_details"]:
    print(detail["caller_signature"], detail["edge"]["provenance"])
# src/v3/types.ZodArray._parse ('tsc',)
# src/v3/types.ZodArray._parse.<anon@2305:14> ('tsc',)
# src/v3/types.ZodTuple._parse ('tsc',)
# src/v3/types.ZodTuple._parse.<anon@3446:38> ('tsc',)
```

### Find the callees of a method

The result holds `source_method` and a list of `callee_details`, with the same edge shape. `tsc` marks an edge from the TypeScript checker, and `defuse` marks an edge from the def-use linker. `import` marks an edge to an external target.

```python
callees = analysis.get_callees(
    source_class_name="src/v3/types.ZodArray",
    source_method_declaration="_parse",
)
for detail in callees["callee_details"]:
    print(detail["callee_signature"], detail["edge"]["provenance"])
# src/v3/types.ZodType._processInputParams ('tsc',)
# src/v3/helpers/parseUtil.addIssueToContext ('tsc',)
# src/v3/helpers/parseUtil.ParseStatus.dirty ('tsc',)
# (builtin).then ('import',)
# (builtin).all ('import',)
# (builtin).map ('import',)
# src/v3/helpers/parseUtil.ParseStatus.mergeArray ('tsc',)
# src/v3/types.ZodArray._parse.<anon@2302:38> ('defuse',)
# src/v3/types.ZodArray._parse.<anon@2305:14> ('defuse',)
# src/v3/types.ZodArray._parse.<anon@2310:49> ('defuse',)
```

### Get the call graph of a class

Get every call edge reachable from the methods of one class. To start from one method, pass its full signature as the second argument.

```python
edges = analysis.get_class_call_graph("src/v3/types.ZodArray")
print(len(edges), "edges")
# 936 edges

for caller, callee in edges[:4]:
    print(caller, "->", callee)
# src/v3/types.ZodArray._parse -> src/v3/types.ZodType._processInputParams
# src/v3/types.ZodArray._parse -> src/v3/helpers/parseUtil.addIssueToContext
# src/v3/types.ZodArray._parse -> src/v3/helpers/parseUtil.ParseStatus.dirty
# src/v3/types.ZodArray._parse -> (builtin).then
```

### Compute reachability

Reachability is a `networkx` query over the call graph. The key of a callable node is its signature, so pass the key to `nx.has_path()` directly.

```python
import networkx as nx

cg = analysis.get_call_graph()

source = "src/v3/types.ZodArray._parse"
target = "src/v3/helpers/parseUtil.makeIssue"

print(nx.has_path(cg, source, target))
# True

print(" -> ".join(nx.shortest_path(cg, source, target)))
# src/v3/types.ZodArray._parse -> src/v3/helpers/parseUtil.addIssueToContext -> src/v3/helpers/parseUtil.makeIssue
```

### Find the call paths between two callables <Badge text="2.0" variant="caution" />

`reaches()` and `call_paths_between()` take a callable name. A name matches a whole signature, or a dotted suffix of one. Each path is a list of hops, and each hop has a `frm` node and a `to` node.

```python
print(analysis.reaches("ZodArray._parse", "makeIssue"))
# True

result = analysis.call_paths_between("ZodArray._parse", "makeIssue")
for path in result.paths:
    nodes = [path.hops[0].frm.callable]
    nodes += [hop.to.callable for hop in path.hops]
    print(" -> ".join(nodes))
# src/v3/types.ZodArray._parse -> src/v3/helpers/parseUtil.addIssueToContext -> src/v3/helpers/parseUtil.makeIssue
```

## Model objects: TSClass and TSCallable

CLDK returns typed model objects, not plain strings. For the full field list of each model, read the [TypeScript API reference](/reference/python-api/typescript/).

### Inspect a TSClass

A `TSClass` holds the methods, the fields, the base classes, the implemented interfaces, and the line span of a class.

```python
tsclass = analysis.get_class("src/v3/types.ZodArray")
print(tsclass.name)
# ZodArray

print(tsclass.signature)
# src/v3/types.ZodArray

print(tsclass.base_classes)
# ['src/v3/types.ZodType']

print(tsclass.start_line, "to", tsclass.end_line)
# 2236 to 2356
```

### Inspect a TSCallable

A `TSCallable` represents a function, a method, a constructor, an accessor, or an arrow function. Its `kind` is one of `function`, `method`, `constructor`, `getter`, `setter`, `arrow`, and `function_expression`. `get_methods_in_class` returns the methods of a class, keyed by name.

```python
methods = analysis.get_methods_in_class("src/v3/types.ZodArray")
method = methods["nonempty"]

print(method.kind, "->", method.return_type)
# method -> ZodArray<T, "atleastone">

print("Async:", method.is_async)
# Async: False

print("Complexity:", method.cyclomatic_complexity)
# Complexity: 1

print(method.code)
# nonempty(message?: errorUtil.ErrMessage): ZodArray<T, "atleastone"> {
#     return this.min(1, message) as any;
#   }
```

### Read the class hierarchy

`get_extended_classes()` returns the base classes of a class. `get_implemented_interfaces()` returns the interfaces that a class implements, and `ZodArray` implements none. `get_sub_classes()` finds the direct subclasses of a class, and it also accepts an interface signature. `get_nested_classes()` always returns `[]` for TypeScript, because the analysis records only methods and fields as the members of a class.

```python
print(analysis.get_extended_classes("src/v3/types.ZodArray"))
# ['src/v3/types.ZodType']

print(analysis.get_implemented_interfaces("src/v3/types.ZodArray"))
# []

subclasses = analysis.get_sub_classes("src/v3/types.ZodType")
print(len(subclasses), sorted(subclasses)[:3])
# 36 ['src/v3/types.ZodAny', 'src/v3/types.ZodArray', 'src/v3/types.ZodBigInt']

print(analysis.get_nested_classes("src/v3/types.ZodArray"))
# []
```

## Source positions <Badge text="2.0" variant="caution" />

### Locate a line

`locate()` resolves a file path and a 1-based line number to the callable that encloses that line. The result also names the type that owns the callable, the module, and the innermost body node. Line 176 of `src/v3/ZodError.ts` is in the function `quotelessJson`. If the line sits at module scope, `callable` is `None` and `diagnostics` holds a `module_scope` code.

```python frame="none"
loc = analysis.locate("src/v3/ZodError.ts", 176)
print(loc.callable.signature)
# src/v3/ZodError.quotelessJson

print(loc.module.path)
# src/v3/ZodError.ts

print([d.code for d in loc.diagnostics])
# []
```

### Read the source of a callable

`get_source()` returns the source text of one callable signature.

```python
print(analysis.get_source("src/v3/ZodError.quotelessJson"))
# quotelessJson = (obj: any) => {
#   const json = JSON.stringify(obj, null, 2);
#   return json.replace(/"([^"]+)":/g, "$1:");
# }
```
