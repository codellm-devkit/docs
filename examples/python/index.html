Python examples

These examples analyze a Python package called my_pkg, the recurring sample across the Python documentation. They are grouped by task: setting up an analysis, querying the symbol table, traversing the call graph, and inspecting the model objects. Each example reflects behavior the SDK guarantees.

Project-based analysis

Python analysis is project-based: point it at a directory of importable Python files with project_path.

Set up the analysis

Section titled “Set up the analysis”

Initialize a CLDK analysis object pointed at your Python project. By default, analysis extracts the symbol table (classes, methods, imports); add analysis_level=AnalysisLevel.call_graph for call-graph queries.

Parallel backends

Backend options live in a PyCodeAnalyzerConfig passed as backend=. Set use_codeql=False to skip CodeQL augmentation and analyze faster (Jedi-only call graph); it defaults to True for enhanced inter-procedural accuracy. Use cache_dir to control where the backend stores its virtualenv and analysis cache (default <project>/.codeanalyzer).

Call graph: callers, callees, reachability

Section titled “Call graph: callers, callees, reachability”

Always set analysis_level

All call-graph operations require analysis_level=AnalysisLevel.call_graph. The default level only builds the symbol table.

Build a call graph

Section titled “Build a call graph”

The call graph is a networkx.DiGraph with edges pointing caller → callee. Useful for reachability and dependency analysis.

Find who calls a method

Section titled “Find who calls a method”

Use get_callers to find all methods that invoke a target method. This is the basis of impact analysis.

Find what a method calls

Section titled “Find what a method calls”

Use get_callees to find all methods that a target method invokes. This provides the dependency view.

Extract call graph for a class

Section titled “Extract call graph for a class”

Get all call edges reachable from a specific class or method.

Compute reachability

Section titled “Compute reachability”

Reachability is a networkx query over the call graph. Extract endpoints from the graph, then use nx.has_path().

Working with the PyClass and PyCallable models

Section titled “Working with the PyClass and PyCallable models”

CLDK returns typed model objects rather than plain strings. Inspect these objects for detailed information about classes and callables.

Section titled “Inspect a PyCallable”
